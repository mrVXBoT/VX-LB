# بررسی چرخهٔ ساخت استخر و تغییر تونل

این بررسی، پذیرش درخواست، انتخاب موتور، انتقال گزینه‌ها، اجرای کار، ثبت نتیجه و
بازیابی را پوشش می‌دهد. هیچ تنظیمی روی سرورهای واقعی کاربر اعمال نشده است.

## ساخت استخر

- نام و پورت‌ها پیش از ورود به آداپتر یکدست و اعتبارسنجی می‌شوند.
- مقصد و نودهای ورودی باید مشخص و متمایز باشند؛ انتخاب تکراری رد می‌شود.
- موتور باید با ترنسپورت انتخابی سازگار باشد و سیاست محیط production را رعایت کند.
- ساخت مستقیم CLI نیز زیر قفل عملیات قرار می‌گیرد؛ رکورد موجود بازنویسی نمی‌شود.
- پذیرش API یک کار صف‌شده ثبت می‌کند؛ موفقیت فقط با حضور و آمادگی تمام اعضای
  درخواست‌شده ثبت می‌شود. ساخت ناقص، حتی با پاسخ موفق موتور، موفق اعلام نمی‌شود.
- کار قدیمی یا تمام‌شده دوباره اجرا نمی‌شود. شکست ایجاد thread قفل دائمی باقی نمی‌گذارد.

## تغییر ترنسپورت و پروفایل

| مسیر | رفتار |
| --- | --- |
| BackPack به BackPack | تغییر مرحله‌ای تنظیمات دو سمت؛ پشتیبان فایل و آزمون مستقل انتقال داده |
| BackPack/کرنل به کرنل | تغییر هر نود، ثبت checkpoint پیش از حذف منبع، بررسی آمادگی مقصد |
| سایر تغییرهای مجاز بین موتورها | پشتیبان کامل پیش از پاک‌سازی؛ بازسازی مقصد و بررسی تمام اعضا |
| تغییر پروفایل در همان موتور | تشخیص تفاوت mode/profile؛ حفظ اعتبارنامه‌های موجود مگر درخواست جایگزینی |
| HTTP به HTTPS و برعکس | عملیات اختصاصی CONNECT؛ مهاجرت مستقیم به خانواده‌های دیگر رد می‌شود |
| پروفایل پردازش بسته | تغییر درجا رد می‌شود؛ باید استخر جداگانه ساخته شود |

تغییر بین موتورها ممکن است اتصال همهٔ اعضا را موقتاً قطع کند. پورت‌ها، اعضا و
تنظیمات DNS حفظ می‌شوند؛ اعتبارنامه‌های موتور جدید ممکن است متفاوت باشند.

شکست پاک‌سازی نادیده گرفته نمی‌شود. شکست ساخت یا ساخت ناقص مقصد، بازگردانی
منبع را آغاز می‌کند. شکست بازگردانی، نسخهٔ پشتیبان و قفل عملیات را حفظ می‌کند.
بازیابی ری‌استارت، هم فاصلهٔ حذف/ساخت رکورد استخر و هم جایگزینی رکورد توسط
آداپتر مقصد را پوشش می‌دهد. رهاسازی صریح کار ناموفق، پشتیبان را آرشیو می‌کند.

## فرم‌ها و API

گزینه‌های ساخت و تغییر از اعتبارسنج مشترک عبور می‌کنند. mode/profile انتخاب‌شده،
فهرست resolverها، MTU، VNI، پورت UDP، PSK و مشخصات TLS بدون حذف خاموش منتقل
می‌شوند. TLS نامعتبر پیش از عملیات تخریبی رد می‌شود. پاسخ وضعیت، آرگومان‌ها و
پشتیبان‌های حاوی اعتبارنامه را منتشر نمی‌کند.

در CLI، تغییر موتور از ابزار وضعیت/MTU جدا شده است؛ ابزارهای قبلی از انتخاب
مستقل تنظیمات رابط در دسترس‌اند.

## شواهد تست

- `tests/test_pool_workflow_lifecycle.py`: ماتریس تمام شناسه‌های فهرست ترنسپورت،
  پذیرش تغییر برای موتورهای مجاز، ارجاع ساخت به آداپتر، رد ورودی نامعتبر،
  موفقیت/شکست/ساخت ناقص، ری‌استارت، بازگردانی، رقابت پذیرش و محافظت اعتبارنامه‌ها.
- `tests/test_transport_change.py`: تغییر مرحله‌ای دو سمت، حفظ تنظیمات و
  بازگردانی نودهای تغییرکرده و بررسی شواهد انتقال داده.
- `tests/test_pool_creation.py` و `tests/test_cli_transport.py`: صف ساخت،
  پیشرفت، بازیابی و مسیر خط فرمان.
- `tests/test_web_client.cjs`: انتخاب پروفایل و انتقال resolver، VNI، پورت و
  مشخصات TLS از فرم تا درخواست، همراه تست‌های قبلی رابط.

آخرین اجرای محلی مجموعهٔ متمرکز: **۱۹۰ تست موفق**. تست مرورگر، بررسی نحو
JavaScript، کامپایل پایتون، Ruff فایل‌های تغییرکرده و `git diff --check` موفق‌اند.

اجرای کامل نهایی در sandbox محلی به منع ایجاد سوکت برخورد کرد؛ نتیجهٔ آن را
موفقیت کامل حساب نمی‌کنیم. workflow جدید `.github/workflows/tests.yml` مجموعهٔ
کامل را روی GitHub Actions اجرا و گزارش JUnit را نگهداری می‌کند. نتیجهٔ آن باید
برای همین commit در بخش Checks بررسی شود. تست‌های آزمایشگاه وابسته به محیط و
صحت تونل روی شبکهٔ واقعی با این تست‌های شبیه‌سازی‌شده اثبات نمی‌شوند.
