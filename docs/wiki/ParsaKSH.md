# ParsaKSH Spoof Tunnel

ParsaKSH/spoof-tunnel یک تانل جعل دوطرفهٔ IP (لایه ۳/۴) به زبان Go/Rust است که جلسهٔ منطقی را از آدرس‌های فیزیکی جدا می‌کند: هر دو سمت آدرس مبدأ بسته‌ها را جعل می‌کنند تا فایروال‌های stateful و DPI مسیر را رد نکنند.

**حالت v3 (UDP-pipe):** کلاینت روی یک پورت UDP گوش می‌دهد، دیتاگرام‌ها را تونل می‌کند و سرور آن‌ها را به یک `forward_target` می‌فرستد. برای سرویس‌های TCP معمولاً یک WireGuard محلی روی این UDP-pipe سوار می‌شود (MTU پیشنهادی 1280).

**چیدمان در VX-LB:** نود ایران «local» است و روی `0.0.0.0:<پورت سرویس>` (اولین پورت استخر) UDP گوش می‌دهد؛ سرور خارج «remote» است، روی `data_port` گوش می‌دهد و به `forward_target` فوروارد می‌کند.

## فیلدهای تنظیم

- `transport`: پروتکل تونل — `udp` (پیش‌فرض)، `icmp`، `icmpv6`، `tcp` (SYN).
- `data_port`: پورت UDP تونل (سرور)، دو سمت مشترک (پیش‌فرض 8090).
- `recv_port`: پورت دریافت کلاینت، دو سمت مشترک (پیش‌فرض 5001).
- `spoof_port`: پورت مبدأ جعل‌شده (پیش‌فرض 443).
- `spoof_ip`: آدرس جعل‌شدهٔ مبدأ کلاینت (ایران).
- `server_spoof_ip`: آدرس جعل‌شدهٔ مبدأ سرور (خارج).
- `forward_target`: مقصد فوروارد روی سرور (`host:port`)؛ خالی = خودکار (خارج:data_port).

## پیش‌نیازها و محدودیت‌ها

- نیازمند `root / CAP_NET_RAW` در هر دو سمت (raw socket).
- هر دو سمت باید بتوانند بستهٔ جعل‌شده بفرستند؛ از ابزار `spoof-tester` پروژه (داخل پنل آن) برای یافتن IPهای معتبر استفاده کنید.
- اگر BCP38/فیلترینگ ورودی در مسیر اعمال شود، جعل عبور نمی‌کند.
- فقط برای زیرساخت‌هایی که مجوز دارید؛ جعل IP در برخی حوزه‌ها غیرقانونی است.

## اگر ساخت یا ارتباط شکست خورد

نقش دو سمت، پروتکل، `data_port`/`recv_port` و دو `spoof_ip` را تطبیق دهید؛ سپس با tcpdump روی سرور، رسیدن بسته‌های جعل‌شده را بررسی کنید. متن خطا و آخرین مرحله را بخوانید و وضعیت را دوباره بگیرید.
