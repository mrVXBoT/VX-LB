# امنیت، پشتیبان‌گیری و بازیابی

## سطح دسترسی

پنل مدیریتی می‌تواند از طریق SSH روی سرورها سرویس و شبکه را تغییر دهد. آن را پشت SSH forwarding یا HTTPS و کنترل دسترسی مناسب قرار دهید. bind روی `0.0.0.0` به معنی عمومی‌شدن احتمالی پنل است. رمز پنل با رمز SSH، توکن Cloudflare، PSK یا رمز موتور یکسان نیست.

نشست مرورگر با کوکی HttpOnly نگهداری می‌شود و ورود محدودیت نرخ دارد؛ این‌ها جایگزین رمز قوی و TLS نیستند. روی HTTPS تنظیم Secure cookie را متناسب با استقرار فعال کنید. خروج نشست را پایان می‌دهد؛ برای توقف تونل از عملیات مربوط استفاده کنید.

## کلیدها و گواهی‌ها

کلید خصوصی روی سمت درست و با دسترسی محدود باقی بماند. کلید عمومی WireGuard محرمانه نیست؛ کلید خصوصی و PSK محرمانه‌اند. گواهی عمومی با کلید خصوصی TLS فرق دارد. مسیر فایل‌های گواهی در فرم معمولاً مسیر **سرور مقصد اجرا** است، نه لپ‌تاپ یا صرفاً میزبان پنل. زمان سیستم و تاریخ انقضا بر TLS اثر دارند.

داشتن mTLS یا IPsec به معنی استتار HTTPS نیست. نام عمومی موتور هم تضمین رمزنگاری همهٔ حالت‌ها نیست؛ رمزنگاری پروفایل را از صفحهٔ مربوط بخوانید.

## دادهٔ حساس پروژه

در نصب معمول، `/opt/vx-lb/data/` شامل inventory، دسترسی SSH، توکن Cloudflare، وضعیت کارها، نسخه‌های پشتیبان و لاگ است. مسیر داده در checkout داخل `data/` است. پوشه باید محدود به `0700` و فایل‌های حساس `0600` باشند. داده را commit، آپلود عمومی یا در Issue پیوست نکنید؛ ماسک‌شدن خطای API به معنی بی‌خطر بودن فایل inventory نیست.

## پشتیبان‌گیری

ابتدا منتظر پایان عملیات تغییر شوید. برای یک snapshot سازگار از کل پوشه، نوشتن پنل/CLI/watchdog را در پنجرهٔ نگهداری متوقف کنید. snapshot را در محل خصوصی و ترجیحاً رمزگذاری‌شده نگه دارید؛ خاموش‌کردن watchdog به‌تنهایی اجرای workerهای پنل را متوقف نمی‌کند.

نمونهٔ تهیهٔ آرشیو پس از توقف نویسنده‌ها:

```bash
sudo install -d -m 700 /root/vxlb-backups
sudo sh -c 'umask 077; tar -czf /root/vxlb-backups/data-backup.tar.gz -C /opt/vx-lb data'
```

نام ثابت این مثال، نسخهٔ قبلی را جایگزین می‌کند؛ برای چند نسل، نام یکتا انتخاب کنید. فایل را از مسیر وب و دستگاه مشترک دور نگه دارید. کیت آفلاین نرم‌افزار، جای پشتیبان داده را نمی‌گیرد.

## بازیابی

نسخه و سالم‌بودن آرشیو را بررسی، نویسنده‌ها را متوقف و دادهٔ فعلی را قبل از جایگزینی جدا نگه دارید. آرشیو مورداعتماد را در مسیر نصب صحیح باز کنید، مالکیت/مجوز را کنترل و سپس پنل/پایش را راه‌اندازی کنید. بازیابی inventory به‌تنهایی سرویس و فایروال سرورهای دور را به همان لحظه برنمی‌گرداند؛ وضعیت واقعی دو سمت باید تطبیق داده شود.

نوشتن inventory اتمیک و همراه قفل و نسل‌های backup است؛ بازیابی خودکار دادهٔ معتبر، موفقیت عملیات نیمه‌تمام شبکه را ثابت نمی‌کند. `pool_backups`، رزرو منابع و اطلاعات pending cleanup را بدون بررسی حذف نکنید.
