# Cloudflare، رکوردها، failover و چرخش IP

## سه کاربرد متفاوت DNS

1. **DNS سرویس کاربر:** آدرس نودهای ایران یا مقصد انتخابی استخر.
2. **دامنهٔ داشبورد:** دسترسی به میزبان مدیریت و Nginx.
3. **delegation برای Slipstream:** هدایت پرس‌وجوی DNS زیردامنه به سرور authoritative خارج.

این سه مورد را یک رکورد یا یک گزینه فرض نکنید.

## پروفایل توکن و Zone

در Cloudflare، پروفایل با نام مشخص و API Token بسازید. برای کشف Zone و مدیریت رکورد، توکن باید روی Zoneهای موردنظر اجازهٔ خواندن Zone و خواندن/ویرایش DNS داشته باشد. از توکن محدود به دامنه‌های لازم استفاده کنید. سپس Zoneها را دریافت یا تازه‌سازی کنید و Zone را انتخاب کنید. فهرست خالی می‌تواند از مجوز ناکافی، حساب اشتباه، token منقضی یا کش قدیمی باشد.

نام پروفایل قابل ویرایش و توکن قابل جایگزینی است. حذف پروفایل را با حذف رکوردهای DNS یکی ندانید. قبل از تغییر، وابستگی استخرها و اعتبار توکن جدید را بررسی کنید. نمایش ماسک‌شدهٔ توکن به معنی آزمون موفق API نیست.

## مدیریت رکورد

نوع، نام، مقدار/فیلدهای نوع، TTL و در انواع مجاز حالت Proxy را مشخص کنید. پنل برای رکوردهای متنی، آدرس، ایمیل و انواع دارای دادهٔ ساختاری، فیلد متناسب نشان می‌دهد؛ [مرجع فرم‌ها](Field-Reference.md) نوع‌های موجود را ثبت کرده است. جست‌وجو/فیلتر فقط نمایش را محدود می‌کند.

برای تونل TCP/UDP عمومی، IPsec، WireGuard یا DNS، روشن‌کردن ابر نارنجی CDN عادی راه عبور آن پروتکل نیست. فقط حامل HTTP سازگار، پورت مجاز و تنظیمات هماهنگ پراکسی می‌توانند از CDN استفاده کنند. WireGuard، Raw TCP و ESP را به عنوان HTTPS معرفی نکنید.

## DNS اختصاصی استخر

در کارت استخر، DNS را باز کنید، Token/Zone/زیردامنه و scope را متناسب با هدف انتخاب کنید و ابتدا پیش‌نمایش بگیرید. تنظیم اختصاصی می‌تواند پیش‌فرض عمومی را جایگزین کند. نام و Zone باید متعلق به هم باشند. پیش‌نمایش و رکوردهای خوانده‌شده را قبل از اعمال بررسی کنید؛ حذف/ویرایش دستی رکوردی که watchdog مدیریت می‌کند ممکن است در ارزیابی بعدی بازنویسی شود.

## خودکار و دستی

حالت خودکار از سلامت نودها و سیاست DNS استفاده می‌کند. حالت دستی یا override انتخاب اپراتور را اعمال می‌کند؛ پیش از بازگشت به خودکار وضعیت هدف را بررسی کنید. کارت DNS باید رکورد مشاهده‌شده و زمان مشاهده را نشان دهد؛ فهرست نودهای سالم با پاسخ واقعی API DNS یکسان نیست.

در سیاست `strict` فقط اعضای HEALTHY وارد انتخاب می‌شوند؛ سیاست انعطاف‌پذیر ممکن است CANARY را هم در نظر بگیرد. IDLE را خودکار سالمِ تأییدشده یا فیلترشده فرض نکنید. نبود نود واجد شرایط را از خطای توکن جدا بررسی کنید.

## چرخش IP

زمان‌بندی می‌تواند پیش‌فرض عمومی یا تنظیم اختصاصی هر استخر باشد. دو حالت وجود دارد: دوره‌ای، بین ۵ تا ۱۰۰۸۰ دقیقه، و روزانه با قالب HH:MM. ساعت روزانه بر مبنای **زمان سیستم سرور مدیریت** است، نه لزوماً ساعت مرورگر شما. برای زمان‌بندی تهران، timezone سرور را صریح بررسی کنید.

چرخش فقط هدف‌های سالم و واجد شرایط را انتخاب می‌کند؛ تاریخچه، IP فعال، نتیجه و زمان بعدی را بخوانید. زمان‌بندی نیازمند دیمن فعال و دسترسی معتبر Cloudflare است. از کارافتادن API، نبود نود سالم، قفل عملیات یا cache DNS می‌تواند مانع نتیجهٔ مورد انتظار شود.

Failover تغییر مقصد DNS است، نه مهاجرت اتصال‌های باز. TTL و cache resolver/کلاینت تعیین می‌کنند کاربران چه زمانی رکورد تازه را ببینند؛ قطع صفر تضمین نمی‌شود.
