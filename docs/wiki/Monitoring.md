# سلامت، لاگ، تأخیر و BBR

## معنی وضعیت‌ها

| وضعیت | برداشت درست |
| --- | --- |
| `PROVISIONING` | ساخت یا آماده‌سازی نود هنوز کامل نشده است |
| `HEALTHY` | شواهد پایش برای سلامت مسیر وجود دارد؛ زمان و پورت‌های بررسی‌شده را ببینید |
| `CANARY` | پذیرش محدود/آزمایشی طبق نتیجه و سیاست پایش؛ هم‌ارز سلامت قطعی نیست |
| `DEGRADED` | نشانهٔ افت کیفیت؛ جزئیات پورت و دلیل را بخوانید |
| `IDLE` | شواهد تازهٔ کافی از ترافیک موجود نیست؛ به‌تنهایی به معنی خرابی یا فیلتر نیست |
| `FILTERED` | شواهد اختلال/فیلتر طبق پایش ثبت شده؛ دلیل و زمان را بررسی کنید |
| `DOWN` | خطای دسترسی، سرویس یا ساخت ناقص؛ متن دلیل مشخص‌کننده است |
| ناشناخته | رابط نمی‌تواند این وضعیت را به سلامت تعبیر کند؛ گزارش خام را بررسی کنید |

SSH یک کانال مدیریتی است. دسترسی آن، عبور TCP/UDP سرویس را ثابت نمی‌کند. به همین ترتیب، نبود کاربر فعال نباید خودکار فیلتر تلقی شود. وضعیت کلی ممکن است از چند پورت و شواهد متفاوت جمع‌بندی شود.

## جزئیات نود

IP، موتور/ترنسپورت، پورت تونل، latency، پورت‌های سرویس، زمان آخرین بررسی و دلیل وضعیت را بررسی کنید. تأخیر نمایش‌داده‌شده نمونهٔ مسیر/پروب موجود است؛ benchmark تضمین‌شدهٔ تجربهٔ تمام کاربران نیست. نبود latency، مقدار صفر واقعی را ثابت نمی‌کند.

«جزئیات اتصال و پایش» پارامترهای فنی را باز می‌کند. «لاگ اتصال» برای مشاهدهٔ رخدادهای مرتبط است؛ لاگ خود پنل، لاگ watchdog و journal سرویس موتور یکی نیستند. قبل از اشتراک‌گذاری، IP خصوصی، دامنه، رمز، توکن و کلید را از خروجی حذف کنید.

## واچ‌داگ و ارزیابی دستی

از تب واچ‌داگ شروع/توقف دیمن و «ارزیابی DNS» را کنترل کنید. نمایش «متصل» برای مرورگر به معنی فعال‌بودن دیمن یا سالم‌بودن تونل نیست. دادهٔ قدیمی پس از قطع API ممکن است روی صفحه بماند؛ هشدار ارتباط و زمان بررسی مهم‌اند. با دریافت دوباره، نتیجه را تطبیق دهید.

## WatTunnel

سلامت این خانواده از `/stats` روی `127.0.0.1` کلاینت ایران خوانده می‌شود، نه از لاگ BackPack. `alive` با `last_rx_age_ms` کمتر از ۴۵ ثانیه `HEALTHY` است. سنِ نبودن `DEGRADED` است و مقدار منفی، یعنی هنوز بستهٔ معتبری نرسیده، `DOWN` است. سکوت طولانی هم `DOWN` است و RTT همان `srtt_ms` است. پایشگر اتصال پورت‌های `/etc/vxlb/wattunnel/client-*.yml` را کنار پورت‌های BackPack تماشا می‌کند. پنجرهٔ لاگ، journal واحد `vxlb-wattun-c-*` و همان فایل اتصال کاربران را با هم نشان می‌دهد. خطوط `no reply from the server` و `lost contact` خطای لینک WatTunnel هستند؛ `USER_SESSION_ACTIVE` و `CLEAN_FLOW` نشست کاربر روی پورت منتشرشده‌اند.

## BBR / Congestion Control

ابزار BBR وضعیت الگوریتم کنترل ازدحام و قابلیت میزبان را بررسی/تنظیم می‌کند. BBR بیشتر به جریان TCP و کرنل مربوط است؛ UDP مسدود، MTU اشتباه، IPsec خراب یا کلید ناهماهنگ را اصلاح نمی‌کند. قبل از اعمال، پشتیبانی کرنل و اثر تغییر بر سرویس‌های دیگر را بررسی کنید. بهبود سرعت را با سرویس واقعی و در شرایط قابل مقایسه بسنجید.

## آزمون WireGuard و VXLAN

WireGuard ابزار وضعیت/handshake و probe اختصاصی دارد؛ شکست probe می‌تواند از UDP، کلید، route، فایروال یا سرویس مقصد باشد. رابط بالا و handshake به‌تنهایی عبور همهٔ پورت‌ها را تضمین نمی‌کنند. VXLAN اطلاعات اینترفیس/روش و وضعیت را نشان می‌دهد؛ VNI، پورت UDP و route هم باید با دو سمت هماهنگ باشند.

پیام اعلان خارجی را با ارسال واقعی اشتباه نگیرید: در این نسخه ارسال اعلان بیرونی پیاده‌سازی عملیاتی نشده است؛ این راهنما آن را قابلیت فعال معرفی نمی‌کند.
