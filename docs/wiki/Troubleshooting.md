# رفع خطا و پرسش‌های رایج

## جدول تشخیص سریع

| نشانه | بررسی اول | اقدام بعدی |
| --- | --- | --- |
| پنل باز نمی‌شود | فرایند وب، bind و پورت، SSH forwarding | روی دستگاه محلی آدرس درست را باز کنید؛ عمومی‌کردن bind اولین راه‌حل نیست |
| ورود ناموفق یا 401 | رمز پنل، نشست، محدودیت نرخ | دوباره وارد شوید؛ رمز SSH را جای رمز پنل وارد نکنید |
| درخواست timeout شده | وضعیت تازهٔ استخر و آخرین job | نتیجه نامشخص است؛ قبل از تکرار حذف/ساخت، وضعیت را بخوانید |
| SSH وصل نمی‌شود | IP، پورت، کاربر، کلید/رمز، فایروال | از میزبان مدیریت دسترسی را آزمایش کنید؛ هیچ کانفیگ موفقی جای SSH لازم را نمی‌گیرد |
| ساخت پذیرفته شده ولی تمام نشده | پیام مرحله و جزئیات نود | منتظر نتیجه بمانید؛ accepted با succeeded فرق دارد |
| ساخت بخشی از استخر شکست خورده | نود ناقص، وابستگی موتور، منابع رزروشده | ابتدا باقی‌مانده‌ها را تعیین تکلیف کنید؛ همان نام را کورکورانه نسازید |
| عملیات دیگر در جریان است | jobهای فعال یا rollback_failed، حتی استخر مخفی با فیلتر | پایان/بازیابی کار را دنبال کنید؛ فایل lock را حذف نکنید |
| حذف نود/استخر شکست می‌خورد | دسترسی هر دو سمت و متن خطا | رفع مشکل و حذف عادی دوباره؛ forget فقط با آگاهی از منابع باقی‌مانده |
| rollback_failed | نسخهٔ پشتیبان و خطای دو سمت | بازگردانی را پس از رفع دسترسی تکرار کنید؛ آزادسازی قفل سلامت را ثابت نمی‌کند |
| سرویس بالا ولی ترافیک قطع است | پورت کاربر، سرویس مقصد، route، MTU، TCP/UDP | آزمون سرویس واقعی و probe موتور؛ صرف systemd active کافی نیست |
| KCP/QUIC/WireGuard قطع است | UDP در دو سمت و مسیر برگشت | بازبودن TCP/443 دلیل بازبودن UDP نیست |
| GRE/IPsec یا overlay امن قطع است | strongSwan، ESP و UDP 500/4500، SA و ماژول‌ها | مشکل رمزنگاری را رفع کنید؛ fail-closed را برای عبور خام خاموش نکنید |
| GRE6/IP6IP6/DC6 قطع است | IPv6/IPv4 موردنیاز همان carrier | آدرس عمومی و route واقعی را کنترل کنید |
| DNS به IP قبلی می‌رود | پاسخ واقعی رکورد، TTL/cache، override و زمان گزارش | هدف استخر و پاسخ resolver را مقایسه کنید؛ اتصال باز مهاجرت نمی‌کند |
| Zone/رکورد دریافت نمی‌شود | مجوز Token و Zone درست | توکن محدود ولی دارای مجوز لازم و refresh فهرست |
| Slipstream راه نمی‌افتد | delegation NS، میزبان A/AAAA، UDP DNS و resolver | از بیرون شبکه delegation را بررسی کنید؛ صرف ثبت A کافی نیست |
| stream زنده قطع است | پراکسی، نشست و polling جایگزین | buffering پراکسی را بررسی و پس از reconnect وضعیت را تازه کنید |
| پس از update ظاهر قبلی است | commit نصب‌شده، restart فرایند، cache مرورگر | پنل را پس از پایان عملیات restart و صفحه را تازه کنید |
| پروفایل غیرفعال/ناموجود است | جدول پشتیبانی همین نسخه | گزینهٔ unsupported را با API دستی فعال نکنید |

## برای گزارش مشکل چه بفرستم؟

نسخه/commit، موتور و شناسهٔ دقیق پروفایل، نقش سرورهای درگیر، مرحلهٔ شکست، زمان رخداد و timezone، متن خطای پاک‌سازی‌شده، تعداد نودها و نتیجهٔ آزمون سرویس را بنویسید. رمز، توکن، کلید خصوصی، inventory کامل و فایل backup را ارسال نکنید. تفاوت شکست سمت ایران و خارج را مشخص کنید.

## آیا هر پروفایل برای هر شبکه بهتر است؟

خیر. UDP مسدود، MTU کم، فایروال دیتاسنتر، IPv6 نامناسب، CPU محدود و TLS/CDN ناسازگار نتایج متفاوت می‌دهند. ابتدا یک زوج را آزمایش و latency، افت بسته، پایداری و سرویس واقعی را مقایسه کنید. تغییر DNS یا فعال‌سازی BBR به‌تنهایی تضمین سرعت نیست.

## آیا پنل ادعای «بدون قطعی» دارد؟

خیر. بعضی تغییرها مرحله‌ای‌اند ولی مهاجرت موتور، restart، DNS cache و پاک‌سازی منابع می‌توانند وقفه داشته باشند. [چرخهٔ عملیات](Pools-and-Operations.md) توضیح می‌دهد چه نتیجه‌ای واقعاً تأیید می‌شود.
